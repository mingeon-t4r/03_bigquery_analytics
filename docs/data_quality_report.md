# Day 2 — NYC Citi Bike 데이터 품질 검증

## 1. 분석 목적

NYC Citi Bike 원본 데이터의 기간, NULL, 시간 순서 및 이용시간 분포를 확인하여 후속 분석에 사용할 데이터의 품질을 평가했다.

발견된 이상값을 일괄 삭제하기보다는 분석 목적에 따라 처리 기준을 구분하는 것을 목표로 했다.

## 2. 데이터 소스

- 원본 테이블: `bigquery-public-data.new_york_citibike.citibike_trips`
- 분석 도구: Google BigQuery
- 원본 Grain: Trip 1건
- 전체 Trip: 58,937,715건

원본 테이블의 한 행은 한 번의 자전거 이용 기록을 의미한다.

## 3. 데이터 기간

| 항목 | 결과 |
|---|---|
| 최초 Trip 시각 | 2013-07-01 00:00:00 |
| 최종 Trip 시각 | 2018-05-31 23:59:59.606000 |
| 분석 데이터 기간 | 2013년 7월 ~ 2018년 5월 |

데이터는 2013년 7월부터 2018년 5월까지의 기록을 포함한다.

2013년과 2018년은 완전한 연간 데이터가 아니므로 연도별 총 이용량을 단순 비교하면 분석 기간 차이의 영향을 받을 수 있다.

## 4. NULL 검증

주요 시간 및 Station 이름 컬럼의 NULL 개수와 비율을 확인했다.

| 컬럼 | NULL 건수 | NULL 비율 |
|---|---:|---:|
| `starttime` | 5,828,994 | 9.89% |
| `stoptime` | 5,828,994 | 9.89% |
| `start_station_name` | 0 | 0.00% |
| `end_station_name` | 0 | 0.00% |

`starttime`과 `stoptime`에서 각각 5,828,994건의 NULL이 확인됐다.

두 컬럼의 NULL 건수가 같다는 사실만으로 동일한 행에서 동시에 NULL이 발생했다고 단정할 수는 없다.

시간대별, 요일별, 월별 이용량 분석에서는 필요한 시간 컬럼이 NULL인 행을 사용할 수 없으므로 해당 분석의 집계 대상에서 제외해야 한다.

반면 시간 정보가 필요하지 않은 분석에서는 관련 컬럼의 NULL만을 이유로 모든 Trip을 제외할 필요는 없다.

## 5. 시간 순서 검증

종료 시간이 시작 시간보다 빠른 Trip을 확인했다.

| 검증 항목 | 결과 |
|---|---:|
| `stoptime < starttime` | 119건 |

정상적인 Trip은 종료 시각이 시작 시각보다 빠를 수 없으므로 해당 119건은 시간 순서가 비정상적인 기록이다.

이러한 데이터는 이동시간 계산이나 시간 순서를 전제로 하는 분석에 영향을 줄 수 있다.

다만 모든 분석에서 동일하게 제외해야 하는 것은 아니므로 분석 목적에 따라 적용할 처리 기준을 구분했다.

## 6. 이용시간 분포 검증

`tripduration`의 기본 통계량을 확인했다.

| 지표 | 결과 |
|---|---:|
| 최소 이용시간 | 60초 |
| 평균 이용시간 | 962.49초 |
| 최대 이용시간 | 19,510,049초 |

최대 이용시간은 평균 이용시간보다 매우 큰 값으로 나타났다.

따라서 평균 이용시간만으로 일반적인 이용시간을 설명하면 일부 극단값의 영향을 받을 수 있다.

그러나 이용시간이 길다는 사실만으로 오류라고 판단할 수는 없으므로 극단값을 임의로 삭제하지 않았다.

## 7. 데이터 품질 검증 결과

| 검증 영역 | 주요 결과 | 해석 |
|---|---|---|
| 데이터 기간 | 2013년 7월 ~ 2018년 5월 | 시작·종료 연도는 부분 기간 |
| 시작 시각 NULL | 5,828,994건 | 시작 시각 기반 분석에서 제외 필요 |
| 종료 시각 NULL | 5,828,994건 | 종료 시각 기반 분석에서 제외 필요 |
| Station 이름 NULL | 확인한 두 컬럼 모두 0건 | 이름 컬럼의 NULL은 발견되지 않음 |
| 시간 순서 오류 | 119건 | 시간 계산에서 처리 기준 필요 |
| 이용시간 극단값 | 최댓값 19,510,049초 | 분포 및 원인 추가 검토 필요 |

이번 검증에서 NULL, 시간 순서 오류 및 극단적인 이용시간이 확인됐다.

다만 검증 대상 컬럼과 규칙이 제한되어 있으므로 원본 데이터의 모든 품질 문제가 식별됐다고 볼 수는 없다.

## 8. 분석 목적에 따른 데이터 처리 기준

### 8.1 시간 정보가 필요한 분석

월별, 요일별, 시간대별 이용량 분석에서는 해당 분석에 사용하는 시간 컬럼이 NULL인 Trip을 제외한다.

출발 시각 기준 분석에는 `starttime`이 필요하며, 도착 시각 기준 분석에는 `stoptime`이 필요하다.

### 8.2 이용시간 분석

이용시간을 계산할 때는 시작 및 종료 시각이 유효해야 한다.

종료 시간이 시작 시간보다 빠른 119건은 시간 순서가 정상적이지 않으므로 제외하거나 별도 이상값 그룹으로 관리하는 것이 적절하다.

### 8.3 Station 분석

Station별 출발·도착량을 계산할 때는 해당 방향의 Station ID가 유효한지 확인해야 한다.

시간 정보가 필요하지 않은 분석이라면 시간 컬럼의 NULL만으로 무조건 제외할 필요는 없다.

다만 이번 프로젝트의 월별 출발 Station Data Mart는 `starttime`과 `start_station_id`가 유효한 Trip을 대상으로 구성했다.

### 8.4 이용시간 극단값

매우 긴 이용시간을 가진 Trip은 원인을 확인하지 않은 상태에서 일괄 삭제하지 않는다.

이용시간 분포와 극단값의 특성을 추가로 확인한 뒤 분석 목적에 맞는 처리 기준을 결정하는 것이 적절하다.

## 9. 후속 검증 범위 및 남은 한계

Day 2에서 확인한 품질 문제 중 다음 항목은 별도의 검증이 필요한 사항으로 남겨뒀다.

- `starttime`과 `stoptime`의 NULL이 동일한 행에서 발생하는지 확인
- NULL이 특정 기간에 집중되어 있는지 확인
- `tripduration`의 중앙값과 분위수 분석
- 이용시간 극단값의 개별 Trip 기록 검토
- 연도별·월별 관측 범위의 세부 확인

후속 프로젝트 단계에서는 월별 Data Mart의 집계 정확성과 관측 월 누락을 별도로 검증했다.

특히 Station 519와 514의 월별 데이터에서 2016년 10월부터 2017년 3월까지 6개월의 관측 공백을 확인했다.

그러나 이러한 후속 검증이 Day 2에서 제시한 모든 품질 문제의 원인을 해결했다는 의미는 아니다.

## 10. 분석의 한계

원본 데이터에서 발견된 NULL과 이상값의 발생 원인은 확인하지 않았다.

`tripduration`의 극단값이 실제 장시간 이용인지 기록 오류인지는 판단하지 않았다.

시간 컬럼의 NULL 비율과 시간 순서 오류 개수는 확인했지만, 모든 오류 유형에 대한 완전한 품질 검증을 수행한 것은 아니다.

또한 분석별 제외 기준이 서로 다르므로 원본 전체 Trip 수와 후속 Data Mart의 집계 Trip 수를 동일하게 해석해서는 안 된다.

## 11. 결론

NYC Citi Bike 원본 데이터에서 시간 컬럼의 NULL, 시간 순서 오류 및 이용시간 극단값을 확인했다.

이상값을 일괄 삭제하지 않고 분석 목적에 따라 필요한 컬럼과 처리 기준을 구분했다.

이러한 검토는 후속 이용 패턴 분석과 Data Mart 구축에서 집계 대상 및 데이터 제외 조건을 정의하는 근거로 활용됐다.
