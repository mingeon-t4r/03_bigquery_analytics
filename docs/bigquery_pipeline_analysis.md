# Day 12 — BigQuery × Python 데이터 분석 파이프라인

## 1. 분석 목적

BigQuery Data Mart를 Python으로 조회하고, 데이터 품질 검증과 Station별 집계를 수행하여 재사용 가능한 분석 흐름을 구성한다.
SQL과 pandas의 집계 결과를 교차 검증하고, 계산 결과가 일치하지 않는 경우 원인을 조사한다.
정상 데이터뿐 아니라 의도적으로 오류를 삽입한 데이터에 대해서도 검증 로직이 작동하는지 확인한다.

## 2. 분석 환경

- Google Cloud Project: `bigquery-analytics-study`
- BigQuery Dataset: `bigquery_learning`
- 분석 테이블: `station_monthly_summary`
- 분석 Grain: Month × Station
- 사용 기술: BigQuery SQL, Python, pandas, Jupyter Notebook
- 인증 방식: Google Cloud Application Default Credentials

Windows 애플리케이션 제어 정책에 의해 `pyarrow` DLL이 차단되어 `to_dataframe()`을 사용할 수 없었다.
따라서 BigQuery 조회 결과를 Python 딕셔너리 리스트로 변환한 뒤 pandas DataFrame을 생성하는 방식으로 분석을 수행했다.

## 3. 데이터 조회 및 품질 검증

BigQuery에서 총 24,876행을 조회했다.
조회한 데이터는 `trip_month`, `station_id`, `trip_count`의 세 컬럼으로 구성됐다.

| 검증 항목 | 결과 |
|---|---:|
| 전체 행 수 | 24,876 |
| NULL | 0건 |
| Month × Station 중복 | 0건 |
| 음수 이용량 | 0건 |
| 전체 이용량 | 53,108,721건 |
| 기존 합계와 일치 | True |

정의한 데이터 품질 조건은 모두 충족했다.
다만 이번 검증은 모든 유형의 데이터 오류가 존재하지 않음을 보장하지 않는다.

## 4. Station별 집계

pandas `groupby()`와 `agg()`를 이용하여 Station별 관측 월 수, 총 이용량, 월평균 이용량을 계산했다.

- 집계 대상 Station: 881개
- 집계 전 전체 이용량: 53,108,721건
- 집계 후 전체 이용량: 53,108,721건
- 전체 이용량 보존 검증: True

Station 519의 검증 결과는 다음과 같다.

| 지표 | 결과 |
|---|---:|
| 관측 월 수 | 53개월 |
| 총 이용량 | 551,078건 |
| 월평균 이용량 | 약 10,397.70건 |

Station 519의 결과는 Day 11에 수행한 분석과 일치했다.

## 5. Station 순위 비교

전체 이용량과 월평균 이용량을 기준으로 각각 상위 10개 Station을 선정했다.

- 전체 이용량 Top 10: 10개
- 월평균 이용량 Top 10: 10개
- 공통 Station: 7개
- 공통 Station ID: 285, 293, 402, 426, 435, 497, 519

월평균 기준에서 새롭게 상위 10개에 포함된 Station은 521, 3255, 3263이었다.

| Station | 관측 월 수 | 총 이용량 | 월평균 이용량 |
|---|---:|---:|---:|
| 521 | 35 | 268,807 | 7,680.20 |
| 3255 | 19 | 140,551 | 7,397.42 |
| 3263 | 17 | 118,676 | 6,980.94 |

전체 이용량 기준으로만 상위 10개에 포함된 Station은 490, 151, 477이었다.

전체 이용량은 누적 수요 규모를 나타내고, 월평균 이용량은 관측 기간당 이용 강도를 나타낸다.
관측 월 수는 실제 운영 기간과 동일하다고 단정할 수 없다.
따라서 운영 의사결정에서는 관측 기간, 시간대별 수요, 실제 자전거 재고 상태 등을 추가로 검토해야 한다.

## 6. SQL과 pandas 집계 교차 검증

BigQuery SQL과 pandas에서 각각 881개 Station의 집계 결과를 생성하고 `FULL OUTER JOIN`에 해당하는 `pd.merge(how="outer")`로 비교했다.

| 검증 항목 | 결과 |
|---|---|
| Station 매칭 | 881개 일치 |
| 관측 월 수 | 전체 일치 |
| 총 이용량 | 전체 일치 |
| 소수점 둘째 자리 평균 비교 | 18개 불일치 |
| 정수 기반 평균 검산 | 전체 일치 |

평균 불일치 18건의 차이는 약 ±0.01이었다.
불일치는 반올림 경계에 있는 값에서 나타났다.

평균의 정의를 이용하여 다음 조건을 검증했다.

`Python 총 이용량 × SQL 관측 월 수 = SQL 총 이용량 × Python 관측 월 수`

검증 결과 881개 Station 모두에서 평균 계산이 일치했다.
따라서 이번 사례에서 확인된 평균 표시값의 차이는 집계 대상이나 총합의 불일치가 아니라 반올림 및 수치 표현 차이와 관련된 것으로 판단했다.

## 7. 재사용 가능한 검증 함수

`validate_data(df, expected_total)` 함수를 작성하여 네 가지 검사를 하나의 함수로 통합했다.

- NULL 검사
- Month × Station 중복 검사
- 음수 이용량 검사
- 기존 전체 이용량과의 합계 검산

정상 데이터에서는 네 가지 검사가 모두 통과했다.
또한 검증 결과가 실패할 경우 `ValueError`를 발생시켜 후속 분석을 중단할 수 있는 조건문을 작성했다.

## 8. Negative Testing

원본 데이터를 변경하지 않기 위해 `df.copy()`로 테스트 데이터를 생성했다.
테스트 데이터의 첫 번째 행에 `trip_count = -100`을 설정했다.

| 검증 항목 | 결과 |
|---|---|
| NULL 검사 | True |
| 중복 검사 | True |
| 음수 검사 | False |
| 합계 검사 | False |
| 전체 검증 | False |

오류 데이터에서 음수 검사와 합계 검사가 실패하는 것을 확인했다.
이를 통해 검증 함수가 정상 데이터만 통과시키는 것이 아니라 일부 비정상 데이터도 감지할 수 있음을 확인했다.

## 9. 분석의 한계

전체 합계 검산은 이전에 확인한 기준값을 사용하므로 원본 데이터의 정확성을 독립적으로 입증하지 않는다.
Station의 관측 월 수는 실제 운영 기간이나 운영 중단 여부를 직접 나타내지 않는다.
월별 출발량 데이터만으로 자전거 부족, 대여 실패, 추가 배치 필요성을 확정할 수 없다.
현재 파이프라인은 Notebook에서 수동 실행하는 구조이며, 예약 실행이나 운영 환경의 자동 모니터링은 구현하지 않았다.
검증 함수는 지정된 네 가지 데이터 품질 조건만 검사한다.

## 10. 결론

BigQuery 데이터를 Python으로 조회하고, 데이터 품질 검증과 Station별 집계를 수행했다.
전체 이용량과 월평균 이용량의 순위 차이를 확인하여 지표 선택이 분석 결과에 미치는 영향을 검토했다.
SQL과 pandas의 집계 결과를 교차 검증하고, 반올림에 따른 차이를 정수 기반 검산으로 구분했다.
재사용 가능한 검증 함수와 오류 데이터 테스트를 통해 분석 파이프라인의 기본적인 신뢰성을 확인했다.
